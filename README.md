# 紀の里 製造予定管理アプリ

紀の里食品向け製造予定作成アプリの実装コード（フェーズ1）。
Netlify（静的サイト + Netlify Functions + Netlify Blobs）での運用を前提とした構成です。

## 構成
- `app_logic.js` — アプリ本体のロジック（画面描画・状態管理・保存処理）
- `app_style.css` — スタイルシート
- `build.js` — `app_logic.js` / `app_style.css` / マスタデータ(JSON) を1枚のHTMLに組み立てるビルドスクリプト
- `data/app_master_data.json` — 商品・グループのマスタデータ（通販520品目・卸329品目）＋通販・卸売とも週別実績履歴（直近2年分）＋卸の得意先マスタ・商品×得意先対応表
- `data/build_sales_history.py` — 通販の受注データ(Excel)から週別実績履歴を集計し、上記マスタ
  データにマージするスクリプト（実行方法は下記「週別実績（前年同期参考）について」を参照）
- `data/build_wholesale_sales_history.py` — 同上の卸売版（卸売の売上データを反映済み、実行方法は
  下記「週別実績（前年同期参考）について」を参照）
- `data/wholesale_customer_product_source.json` — 卸の得意先別販売実績表から書き起こした
  「得意先×商品×年間数量」の元データ
- `data/build_wholesale_customers.py` — 上記の元データから卸の得意先マスタ・商品×得意先の
  対応表を作り、上記マスタデータにマージするスクリプト（下記「卸売の取引先グループ分けについて」を参照）
- `netlify/functions/state.mjs` — 保存データを読み書きするNetlify Function（`GET/POST /api/state`）
- `netlify.toml` — Netlifyのビルド／Functions設定
- `package.json` — ビルドスクリプトと依存パッケージ（`@netlify/blobs`）
- `public/index.html` — ビルド後の成果物（Netlifyが公開するファイル。手元でも `npm run build` で再生成できます）

## ビルド方法
```
npm install
npm run build
```
`public/index.html` に単一HTMLファイルが出力されます。Netlifyにデプロイする際は
このコマンドをビルドコマンドとして自動実行するよう `netlify.toml` に設定済みです。

## 保存の仕組み
- **Netlifyで運用する場合**：`netlify/functions/state.mjs` が Netlify Blobs
  （Netlifyが提供するシンプルなデータ保存機能）にアプリの状態を1件のレコードとして
  保存します。読み込みは `GET /api/state`、保存は `POST /api/state` で行います。
  2人が同時に保存しようとした場合はバージョン番号で競合を検知し、後から保存しようと
  した側には「他の方が先に保存しました」という通知を出し、最新の内容を読み込み直す
  仕組みになっています（Claude Artifactの競合検知と同じ考え方です）。
- **Claude Artifactのプレビュー内で開いた場合**（動作確認用）：従来どおり
  `window.claude.use('artifact')` でページ自身を書き換えて保存します。
- どちらの保存先も利用できない環境（単なる静的プレビューなど）で開いた場合は、
  自動的に「閲覧のみ・保存不可」の表示になり、安全側に倒れます。

## Netlifyへのデプロイ手順（初回のみ・ユーザー側の作業）
1. https://app.netlify.com にログイン（GitHubアカウントでのログインが簡単です）
2. 「Add new site」→「Import an existing project」→ GitHubを選択し、
   このリポジトリ（`kinosatonaoki-crypto/seizoukanri`）を選択
3. ビルド設定は `netlify.toml` から自動的に読み込まれます（そのままで問題ありません）
4. 「Deploy site」をクリック
5. 初回デプロイが完了すると、Netlifyが発行したURL（例: `xxxx.netlify.app`）でアプリに
   アクセスできるようになります。Netlify Blobsは追加設定なしで自動的に使えます。

以降、GitHubにコード変更をpushするたびにNetlifyが自動的に再ビルド・再デプロイします。

## フェーズ1の範囲
- 通販：週次計画／月次計画／グループ並び順／印刷プレビュー／OCR取込
- 卸売：週次計画／月次計画／取引先並び順／印刷プレビュー／OCR取込
- 確定／下書きワークフロー、製造メモ＋履歴

## OCR取込・スマホ撮影について
紙の伝票・注文書などをスマホで撮影し、数量の入力を補助する機能です。各チャネル（通販／卸）に
「📷 OCR取込」タブがあります。

- 文字認識には [Tesseract.js](https://github.com/naptha/tesseract.js)（CDN経由で読み込み、完全に
  ブラウザ内で動作・外部サーバーへの送信なし）を使用しています。**印刷された文字向け**の機能で、
  手書きの精度は高くありません。
- 認識結果は行ごとに「検出テキスト・候補の商品・数量」として一覧表示され、内容を確認・修正して
  チェックを入れた行だけを今週の入力欄に反映します。反映しても自動保存はされないため、内容を
  確認してから通常どおり「下書き保存」／「この週を確定する」を押してください。
- 商品名のマッチングは文字の類似度（Dice係数）による目安のマッチです。候補が的外れな場合は
  プルダウンから正しい商品を選び直せます。
- **実運用で試した結果、1つのセルが数ピクセルしかないような密集した数値表（スプレッドシート
  形式で出力される日別集計表など）は、文字サイズの都合上ほぼ読み取れないことが分かっています。**
  この機能は「1行＝1商品名＋1数量」程度のシンプルな伝票・注文書向けです。びっしり詰まった
  集計表を取り込みたい場合は、OCRではなくExcel/CSVなど元データそのものを直接インポートする方式
  （下記「週別実績」もその一例）を検討してください。

## 週別実績（前年同期参考）について
週次計画の入力欄に「参考（同時期実績）: 前年◯◯個／前々年◯◯個」という実績ベースの参考値を
表示しています。これは受注データ（Excelエクスポート、商品コード×受注日×数量などを含む明細
データ）を、通販は `data/build_sales_history.py`、卸売は `data/build_wholesale_sales_history.py`
で商品コード×週（月曜始まり）に集計し、`data/app_master_data.json` の `salesHistory.retail` /
`salesHistory.wholesale` に埋め込んだものです。通販・卸売とも同じ仕組みを共有しています。

- 対象は現在のマスタ（`retailProducts` / `wholesaleProducts`）に存在する商品コードのみ。
  値引き・ポイント・送料・箱代などの非商品行や、現在は製造対象外・廃盤になった商品コードは
  自動的に除外されます。
- 保持期間は直近2年分（同じ週の「1年前」「2年前」の両方を参照できるようにするため）。
- 卸売も2026年8月に届いた実データ（「卸_売上データ」、シート「売上データ」・列 出荷日／商品コード／
  総数量を使用）を集計済みで、卸329品目すべてに前年・前々年の週別実績が入っています。通販と
  まったく同じ仕組みを共有しているため、参考表示・自動入力とも卸売で実データのまま動作します。
- **前年の同時期実績がある商品は、製造予定数の欄に最初から「前年実績を10個単位に切り上げた数」
  が入力された状態で表示されます**（例: 前年114個→120個、前年110個→110個、前年1個→10個）。
  ボタンを押す必要はありません。まだ数量を入力・確定していない週を開いただけの状態（下書き
  保存もしていない状態）でも、月次計画画面や印刷プレビューの合計にはこの前年ベースの数値が
  そのまま反映されるため、月初めなどまだ何も入力していない時点でも「前年実績ベースのおおまか
  な予想」として月次の合計を確認・印刷できます。前年実績が無い商品（新商品など）は0（空欄）
  のままです。
- 表示された数量は、状況に応じてそのまま入力欄を書き換えて増減させてください（通常の入力操作と
  同じです）。1つの商品の数量を書き換えても、他の商品の前年実績ベースの数値は変わりません。
- 週次計画画面の「🔄 前年実績にリセット」ボタン（通販・卸売どちらにもあります）は、通販の
  キャンペーンを後から追加した場合など、前年実績（＋通販はキャンペーン増加分）の数値に一括で
  戻したいときに使います。既に入力済みの数量を上書きする場合は確認が入ります。リセットしただけ
  では保存されないため、内容を確認してから通常どおり保存してください。

**データを更新する場合**（新しい売上データのExcelエクスポートが手に入ったとき）：
```
cd data
python3 build_sales_history.py <通販の受注データ.xlsx>
python3 build_wholesale_sales_history.py <卸売の売上データ.xlsx>
cd ..
npm run build
```
その後、通常どおり `git add / commit / push` してください。**受注・売上データのExcelファイル
自体は金額入りの生データのため、リポジトリにはコミットしないでください。**
卸売の売上データは通販の受注データとシート名・列の並びが違うため（`build_wholesale_sales_history.py`
冒頭の `COL_*` 定数・`--sheet` は2026年8月の実データ「シート:売上データ、列:出荷日／商品コード／
総数量」に合わせて設定済みです）、次に別形式のファイルが届いた場合は改めて確認・修正してください。

## 実施中のキャンペーン（増加分の登録）について
通販の週次計画画面の上部に「📣 現在実施中のキャンペーン」という帯が表示されます。お中元・お歳暮の
DMやカタログ、催事など、前年実績だけでは読めない上振れが見込まれる場合に、その週について
「対象商品・施策名・増加数量・メモ（任意）」を登録できます（「＋ 増加分を追加」ボタン）。

- 登録したキャンペーンは、その商品の製造予定数（前年実績ベースの初期値）に自動で加算された
  うえで10個単位に切り上げられます（例: 前年114個＋キャンペーン200個＝314個→320個）。
  まだその週の数量を編集していない場合は、キャンペーンを登録した時点で自動的に反映されます。
  既に数量を編集済み・確定済みの週にキャンペーンを後から追加した場合は、「🔄 前年実績に
  リセット」ボタンで反映し直してください。
- キャンペーンは表示中の週に紐づきます。他の週を見ているときは、その週に登録されたキャンペーンが
  表示されます。
- 登録・削除しただけでは保存されないため、内容を確認してから通常どおり保存してください。

## 昨年同時期のメモ表示について
週次・月次計画画面の製造メモ欄の下に、「昨年同時期のメモ」（週次）／「昨年同月のメモ」（月次）が
自動的に表示されます。今書いたメモは来年の同じ時期を見たときにここに表示される、という仕組みです
（メモを書く・保存する操作自体は既存の「製造メモ」欄と同じです）。該当する過去のメモが無い場合は
何も表示されません。より広い範囲のメモを探したい場合は、従来どおり「🗂 メモ履歴を見る」からキーワード
検索できます。

## 印刷プレビューの印刷について
印刷プレビュー画面の「🖨 このページを印刷」ボタンは、ブラウザ標準の印刷機能（`window.print()`）を
呼び出します。画面上のツールバーなどは印刷時に自動的に非表示になり、A4縦・余白15mmで製造予定表
のみが印刷されるように `@media print` のCSSを設定済みです。実際にPDF出力して見た目を確認済みです。

印刷プレビュー画面の上部に「週次で印刷」「月次で印刷」の切り替えがあり、月次を選ぶとその月の
製造予定「月合計」（各週の入力値を積み上げた合計）を印刷できます。月の切り替えは矢印ボタンで
行います。まだ数量が入力されていない月を選んだ場合は、その旨のメッセージのみが表示されます。

## 卸売の取引先グループ分けについて
卸の週次計画・月次計画・印刷プレビューは、商品を「主にどの取引先が買っているか」でグループ分けして
表示します（通販の「商品グループ」と同じ考え方で、グループ名が取引先名になったものです）。

- 得意先別の年間販売実績表（PDFの「販売クロス分析表」）を書き起こした
  `data/wholesale_customer_product_source.json` をもとに、`data/build_wholesale_customers.py` で
  「得意先マスタ（41社）」と「商品×得意先の対応表」を作り、`app_master_data.json` にマージしています。
  現時点で卸329品目すべてに取引先を紐付けられています。
- 1つの商品は、最も数量の多い取引先1社だけに紐付けてグループ分けしています。複数の取引先が
  同じ商品を買っている場合は、商品名の横に「（他◯社）」と表示されます（例：梅きらら70gは
  とれとれ市場が主な取引先ですが、他に2社が購入しています）。
- **製造予定数はこれまでどおり商品ごとの合計を1つだけ入力する形式のままです。** 取引先ごとに
  「何個ずつ作るか」を別々に管理する機能ではありません（＝取引先別の内訳数量そのものはまだ
  持っていません）。今回できるようになったのは、あくまで商品リストを取引先単位で見やすく
  整理して表示することです。
- 卸売の「週次実績参考・前年実績からの自動入力」は、実データ（2年分）を反映済みで、通販と
  まったく同じ仕組みで動作しています（上記「週別実績（前年同期参考）について」を参照）。
- 卸売の週次計画画面に「取引先並び順」タブを追加しました。通販の「グループ並び順」と同じ操作
  （▲▼で並び替え、「初期値（年間売上順）に戻す」）で、取引先グループの表示順を変更できます。

**書き起こしデータを更新する場合**（新しい得意先別販売実績表が手に入ったとき）：
`data/wholesale_customer_product_source.json` を書き起こし直してから、
```
cd data
python3 build_wholesale_customers.py
cd ..
npm run build
```
を実行し、通常どおり `git add / commit / push` してください。

## 卸売の「今月の特記事項」（増減分の登録）について
卸の月次計画画面の上部に「📝 今月の特記事項」という帯が表示されます。取引先の催事出店・
スポット発注・取引縮小など、前年実績だけでは読めない増減が見込まれる場合に、その月について
「対象商品・件名・増減数量・メモ（任意）」を登録できます（「＋ 特記事項を追加」ボタン）。
通販の「実施中のキャンペーン」機能の卸売版にあたりますが、次の点が異なります。

- **月単位で登録します**（通販のキャンペーンは週単位）。登録した増減数量は、その月に含まれる
  各週の製造予定数（前年実績ベースの初期値）へ均等に割り振られたうえで合算され、10個単位に
  切り上げられます（例：ある月が4週あり、特記事項で+300個を登録した場合、1週あたり+75個が
  各週の前年実績に加算されます）。まだその週の数量を編集していない場合は自動的に反映され、
  既に編集・確定済みの週に後から追加した場合は「🔄 前年実績にリセット」ボタンで反映し直して
  ください。
- **増減数量はプラス・マイナスどちらも入力できます**（通販のキャンペーンは増加のみ）。マイナス
  を登録すると赤字で表示され、前年実績から差し引かれます（合計が0を下回る場合は0個になります）。
- 特記事項は表示中の月に紐づきます。他の月を見ているときは、その月に登録された特記事項が
  表示されます。
- 登録・削除しただけでは保存されないため、内容を確認してから通常どおり保存してください。
- 前年実績データ（`salesHistory.wholesale`）は反映済みのため、登録した特記事項はすぐに
  前年実績ベースの製造予定数へ加算されます。
