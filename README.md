# 紀の里 製造予定管理アプリ

紀の里食品向け製造予定作成アプリの実装コード（フェーズ1）。
Netlify（静的サイト + Netlify Functions + Netlify Blobs）での運用を前提とした構成です。

## 構成
- `app_logic.js` — アプリ本体のロジック（画面描画・状態管理・保存処理）
- `app_style.css` — スタイルシート
- `build.js` — `app_logic.js` / `app_style.css` / マスタデータ(JSON) を1枚のHTMLに組み立てるビルドスクリプト
- `data/app_master_data.json` — 商品・グループのマスタデータ（通販520品目・卸329品目）＋通販の週別実績履歴（直近2年分）
- `data/build_sales_history.py` — 受注データ(Excel)から週別実績履歴を集計し、上記マスタデータに
  マージするスクリプト（実行方法は下記「週別実績（前年同期参考）について」を参照）
- `netlify/functions/state.mjs` — 保存データを読み書きするNetlify Function（`GET/POST /api/state`）
- `netlify.toml` — Netlifyのビルド／Functions設定
- `package.json` — ビルドスクリプトと依存パッケージ（`@netlify/blobs`）
- `public/index.html` — ビルド後の成果物（Netlifyが公開するファイル。手元でも `npm run build` で再生成できます）

## ビルド方法
```
npm install
npm run build
```
`public/index.html` に単一HTMLファイルが出力されます。Netlifyにデプロイする際は
このコマンドをビルドコマンドとして自動実行するよう `netlify.toml` に設定済みです。

## 保存の仕組み
- **Netlifyで運用する場合**：`netlify/functions/state.mjs` が Netlify Blobs
  （Netlifyが提供するシンプルなデータ保存機能）にアプリの状態を1件のレコードとして
  保存します。読み込みは `GET /api/state`、保存は `POST /api/state` で行います。
  2人が同時に保存しようとした場合はバージョン番号で競合を検知し、後から保存しようと
  した側には「他の方が先に保存しました」という通知を出し、最新の内容を読み込み直す
  仕組みになっています（Claude Artifactの競合検知と同じ考え方です）。
- **Claude Artifactのプレビュー内で開いた場合**（動作確認用）：従来どおり
  `window.claude.use('artifact')` でページ自身を書き換えて保存します。
- どちらの保存先も利用できない環境（単なる静的プレビューなど）で開いた場合は、
  自動的に「閲覧のみ・保存不可」の表示になり、安全側に倒れます。

## Netlifyへのデプロイ手順（初回のみ・ユーザー側の作業）
1. https://app.netlify.com にログイン（GitHubアカウントでのログインが簡単です）
2. 「Add new site」→「Import an existing project」→ GitHubを選択し、
   このリポジトリ（`kinosatonaoki-crypto/seizoukanri`）を選択
3. ビルド設定は `netlify.toml` から自動的に読み込まれます（そのままで問題ありません）
4. 「Deploy site」をクリック
5. 初回デプロイが完了すると、Netlifyが発行したURL（例: `xxxx.netlify.app`）でアプリに
   アクセスできるようになります。Netlify Blobsは追加設定なしで自動的に使えます。

以降、GitHubにコード変更をpushするたびにNetlifyが自動的に再ビルド・再デプロイします。

## フェーズ1の範囲
- 通販：週次計画／月次計画／グループ並び順／印刷プレビュー／OCR取込
- 卸売：週次計画／月次計画（商品別合計のみ）／印刷プレビュー／OCR取込
- 確定／下書きワークフロー、製造メモ＋履歴

## OCR取込・スマホ撮影について
紙の伝票・注文書などをスマホで撮影し、数量の入力を補助する機能です。各チャネル（通販／卸）に
「📷 OCR取込」タブがあります。

- 文字認識には [Tesseract.js](https://github.com/naptha/tesseract.js)（CDN経由で読み込み、完全に
  ブラウザ内で動作・外部サーバーへの送信なし）を使用しています。**印刷された文字向け**の機能で、
  手書きの精度は高くありません。
- 認識結果は行ごとに「検出テキスト・候補の商品・数量」として一覧表示され、内容を確認・修正して
  チェックを入れた行だけを今週の入力欄に反映します。反映しても自動保存はされないため、内容を
  確認してから通常どおり「下書き保存」／「この週を確定する」を押してください。
- 商品名のマッチングは文字の類似度（Dice係数）による目安のマッチです。候補が的外れな場合は
  プルダウンから正しい商品を選び直せます。
- **実運用で試した結果、1つのセルが数ピクセルしかないような密集した数値表（スプレッドシート
  形式で出力される日別集計表など）は、文字サイズの都合上ほぼ読み取れないことが分かっています。**
  この機能は「1行＝1商品名＋1数量」程度のシンプルな伝票・注文書向けです。びっしり詰まった
  集計表を取り込みたい場合は、OCRではなくExcel/CSVなど元データそのものを直接インポートする方式
  （下記「週別実績」もその一例）を検討してください。

## 週別実績（前年同期参考）について
週次計画の入力欄に、通販商品については「参考（同時期実績）: 前年◯◯個／前々年◯◯個」という
実績ベースの参考値を表示しています。これは受注データ（Excelエクスポート、商品コード×受注日×
数量などを含む明細データ）を、`data/build_sales_history.py` で商品コード×週（月曜始まり）に
集計し、`data/app_master_data.json` の `salesHistory.retail` に埋め込んだものです。

- 対象は現在のマスタ（`retailProducts`）に存在する商品コードのみ。値引き・ポイント・空タル代
  などの非商品行や、現在は製造対象外・廃盤になった商品コードは自動的に除外されます。
- 保持期間は直近2年分（同じ週の「1年前」「2年前」の両方を参照できるようにするため）。
- 卸売については、対応する受注データがまだないため実績参考は表示していません
  （商品別合計のみでの運用は従来どおりです）。
- **通販の製造予定数は、前年の同時期実績がある商品について、最初から「前年実績を10個単位に
  切り上げた数」が入力された状態で表示されます**（例: 前年114個→120個、前年110個→110個、
  前年1個→10個）。ボタンを押す必要はありません。まだ数量を入力・確定していない週を開いた
  だけの状態（下書き保存もしていない状態）でも、月次計画画面や印刷プレビューの合計にはこの
  前年ベースの数値がそのまま反映されるため、月初めなどまだ何も入力していない時点でも
  「前年実績ベースのおおまかな予想」として月次の合計を確認・印刷できます。
  前年実績が無い商品（新商品など）は0（空欄）のままです。
- 表示された数量は、状況に応じてそのまま入力欄を書き換えて増減させてください（通常の入力操作と
  同じです）。1つの商品の数量を書き換えても、他の商品の前年実績ベースの数値は変わりません。
- 週次計画画面の「🔄 前年実績にリセット」ボタンは、キャンペーンを後から追加した場合など、
  前年実績＋キャンペーン増加分の数値に一括で戻したいときに使います。既に入力済みの数量を
  上書きする場合は確認が入ります。リセットしただけでは保存されないため、内容を確認してから
  通常どおり保存してください。

**データを更新する場合**（新しい受注データのExcelエクスポートが手に入ったとき）：
```
cd data
python3 build_sales_history.py <新しい受注データ.xlsx>
cd ..
npm run build
```
その後、通常どおり `git add / commit / push` してください。**受注データのExcelファイル自体は
金額入りの生データのため、リポジトリにはコミットしないでください。**

## 実施中のキャンペーン（増加分の登録）について
通販の週次計画画面の上部に「📣 現在実施中のキャンペーン」という帯が表示されます。お中元・お歳暮の
DMやカタログ、催事など、前年実績だけでは読めない上振れが見込まれる場合に、その週について
「対象商品・施策名・増加数量・メモ（任意）」を登録できます（「＋ 増加分を追加」ボタン）。

- 登録したキャンペーンは、その商品の製造予定数（前年実績ベースの初期値）に自動で加算された
  うえで10個単位に切り上げられます（例: 前年114個＋キャンペーン200個＝314個→320個）。
  まだその週の数量を編集していない場合は、キャンペーンを登録した時点で自動的に反映されます。
  既に数量を編集済み・確定済みの週にキャンペーンを後から追加した場合は、「🔄 前年実績に
  リセット」ボタンで反映し直してください。
- キャンペーンは表示中の週に紐づきます。他の週を見ているときは、その週に登録されたキャンペーンが
  表示されます。
- 登録・削除しただけでは保存されないため、内容を確認してから通常どおり保存してください。

## 昨年同時期のメモ表示について
週次・月次計画画面の製造メモ欄の下に、「昨年同時期のメモ」（週次）／「昨年同月のメモ」（月次）が
自動的に表示されます。今書いたメモは来年の同じ時期を見たときにここに表示される、という仕組みです
（メモを書く・保存する操作自体は既存の「製造メモ」欄と同じです）。該当する過去のメモが無い場合は
何も表示されません。より広い範囲のメモを探したい場合は、従来どおり「🗂 メモ履歴を見る」からキーワード
検索できます。

## 印刷プレビューの印刷について
印刷プレビュー画面の「🖨 このページを印刷」ボタンは、ブラウザ標準の印刷機能（`window.print()`）を
呼び出します。画面上のツールバーなどは印刷時に自動的に非表示になり、A4縦・余白15mmで製造予定表
のみが印刷されるように `@media print` のCSSを設定済みです。実際にPDF出力して見た目を確認済みです。

印刷プレビュー画面の上部に「週次で印刷」「月次で印刷」の切り替えがあり、月次を選ぶとその月の
製造予定「月合計」（各週の入力値を積み上げた合計）を印刷できます。月の切り替えは矢印ボタンで
行います。まだ数量が入力されていない月を選んだ場合は、その旨のメッセージのみが表示されます。
